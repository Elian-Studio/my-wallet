# 대시보드 E2E 테스트 플랜

## 개요

| 항목 | 내용 |
|------|------|
| 대상 페이지 | `/dashboard` |
| 컴포넌트 | `DashboardPage`, `SummaryCard`, `BudgetSummary`, `HoldingsSummary`, `RecentActivity` |
| 데이터 훅 | `useMonthlySummary`, `useBudgetAnalysis`, `usePortfolioSummary`, `useHoldings`, `useRecentActivity` |
| 인증 방식 | `fixtures.ts` — `authenticatedPage` fixture (자동 로그인 후 `/dashboard` 도달) |
| 기준 URL | `http://localhost:3000` |

---

## 테스트 시나리오

---

### TC-01. 페이지 진입 및 헤딩 렌더링

**전제조건**
- 로그인된 사용자
- 백엔드 API 정상 응답

**단계**
1. `/dashboard`로 이동한다.
2. 페이지 `h1` 텍스트를 확인한다.
3. 부제목(현재 월 표시)을 확인한다.

**기대결과**
- `h1` 요소에 `"대시보드"` 텍스트가 표시된다.
- 부제목에 `"YYYY년 M월 현황"` 형식의 문자열이 포함된다.

---

### TC-02. 요약 카드 4개 렌더링

**전제조건**
- 이번 달 수입·지출 데이터와 포트폴리오 데이터가 존재한다.

**단계**
1. `/dashboard`로 이동한다.
2. API 응답을 기다린 후(`animate-pulse` 사라짐) 카드 목록을 확인한다.

**기대결과**
- `"이번 달 수입"` 카드: 금액이 emerald 색상으로 표시된다.
- `"이번 달 지출"` 카드: 금액이 red 색상으로 표시되고, `"저축 N원"` 서브텍스트가 있다.
- `"포트폴리오 평가액"` 카드: 금액과 `"투자원금 N원"` 서브텍스트가 있다.
- `"미실현 손익"` 카드: 부호가 포함된 금액과 수익률(%)이 표시된다.
- 4개 카드 모두 화면에 visible 상태이다.

---

### TC-03. 미실현 손익 색상 — 수익 시

**전제조건**
- 포트폴리오의 `totalUnrealizedGain > 0` 데이터가 존재한다.

**단계**
1. `/dashboard`로 이동하여 `"미실현 손익"` 카드를 찾는다.
2. 금액 요소의 클래스를 확인한다.

**기대결과**
- 금액 텍스트에 `"+"` 부호가 포함된다.
- 금액 요소가 emerald(초록) 색상 클래스를 갖는다.
- 수익률이 양수(`+N.NN%`)로 표시된다.

---

### TC-04. 미실현 손익 색상 — 손실 시

**전제조건**
- 포트폴리오의 `totalUnrealizedGain < 0` 데이터가 존재한다 (별도 테스트 계정 또는 MSW 목업).

**단계**
1. `/dashboard`로 이동하여 `"미실현 손익"` 카드를 찾는다.
2. 금액 요소의 클래스를 확인한다.

**기대결과**
- 금액 요소가 red 색상 클래스를 갖는다.
- 수익률이 음수(`-N.NN%`)로 표시된다.

---

### TC-05. 예산 달성률 섹션 — 진행 바 렌더링

**전제조건**
- 이번 달 예산(`BudgetAnalysisItem`) 데이터가 1개 이상 존재한다.

**단계**
1. `/dashboard`로 이동한다.
2. `"예산 달성률"` 카드 안에서 각 카테고리 항목을 확인한다.

**기대결과**
- 카테고리명 텍스트가 표시된다.
- 각 항목에 `role="progressbar"` 요소가 존재한다.
- 진행 바의 `aria-valuenow`(또는 `value`)가 0–100 사이의 정수이다.
- `"실적 N원"` 및 `"예산 N원"` 텍스트가 각 항목에 표시된다.

---

### TC-06. 예산 초과 항목 — 경고 표시

**전제조건**
- `achievementRate > 100` 인 예산 항목이 존재한다.

**단계**
1. `/dashboard`로 이동한다.
2. `"예산 달성률"` 섹션에서 초과 항목을 찾는다.

**기대결과**
- 해당 항목에 `"예산 초과: N원"` 텍스트가 표시된다.
- 진행 바가 destructive(붉은) 색상으로 렌더링된다.

---

### TC-07. 보유 종목 요약 — Top 5 렌더링

**전제조건**
- 보유 종목(`HoldingItem`) 데이터가 5개 이상 존재한다.

**단계**
1. `/dashboard`로 이동한다.
2. `"보유 종목 요약"` 카드 안의 종목 목록을 확인한다.

**기대결과**
- 최대 5개 종목만 표시된다 (6번째 이후는 노출되지 않는다).
- 각 종목에 종목명, 종목코드, 비중(%), 평가액, 미실현 손익률이 표시된다.
- 수익 종목은 emerald 색상, 손실 종목은 red 색상으로 표시된다.

---

### TC-08. 최근 활동 타임라인 — 혼합 항목 렌더링

**전제조건**
- 거래(budget) 내역과 매매(stock) 내역이 모두 존재한다.

**단계**
1. `/dashboard`로 이동한다.
2. `"최근 활동"` 카드 내의 항목 목록을 확인한다.

**기대결과**
- 활동 항목이 날짜 내림차순으로 정렬된다.
- 각 항목에 타입 뱃지(`수입` / `지출` / `저축` / `매수` / `매도`)가 표시된다.
- 각 항목에 설명 텍스트, 날짜, 금액이 표시된다.
- 최대 10개 항목이 표시된다.

---

### TC-09. 빈 상태 — 데이터 없음

**전제조건**
- 이번 달 거래 내역, 예산, 보유 종목, 포트폴리오가 모두 비어 있는 계정.

**단계**
1. 빈 계정으로 로그인 후 `/dashboard`로 이동한다.
2. 각 섹션의 빈 상태 메시지를 확인한다.

**기대결과**
- `"이번 달 예산 데이터가 없습니다."` 텍스트가 예산 섹션에 표시된다.
- `"보유 종목이 없습니다."` 텍스트가 종목 섹션에 표시된다.
- `"최근 활동이 없습니다."` 텍스트가 활동 섹션에 표시된다.
- 요약 카드의 수치는 `0원`으로 표시된다.

---

### TC-10. 로딩 스켈레톤 상태

**전제조건**
- 네트워크 응답을 인위적으로 지연시킬 수 있는 환경 (Playwright route intercept 또는 느린 네트워크 조건).

**단계**
1. API 응답을 지연시키도록 라우트를 인터셉트한다.
2. `/dashboard`로 이동하고 응답 전 상태를 스냅샷한다.

**기대결과**
- 요약 카드 4개 내부에 `animate-pulse` 스켈레톤 요소가 존재한다.
- `"예산 달성률"` 섹션에 스켈레톤 행(4줄)이 표시된다.
- `"보유 종목 요약"` 섹션에 스켈레톤 행(5줄)이 표시된다.
- `"최근 활동"` 섹션에 스켈레톤 행(5줄)이 표시된다.
- 실제 데이터 텍스트(금액, 종목명 등)는 보이지 않는다.

---

### TC-11. 사이드바 네비게이션 — 가계부 페이지 이동

**전제조건**
- 로그인된 사용자, 화면 폭 1280px 이상 (데스크톱 사이드바 표시).

**단계**
1. `/dashboard`로 이동한다.
2. 사이드바에서 `"가계부"` 버튼을 클릭하여 메뉴를 펼친다.
3. `"거래 내역"` 링크를 클릭한다.

**기대결과**
- URL이 `/budget/transactions`로 변경된다.
- 가계부 메뉴 항목이 active 스타일(bg-accent)로 강조된다.

---

### TC-12. 사이드바 네비게이션 — 주식 페이지 이동

**전제조건**
- 로그인된 사용자, 화면 폭 1280px 이상.

**단계**
1. `/dashboard`로 이동한다.
2. 사이드바에서 `"주식"` 버튼을 클릭하여 메뉴를 펼친다.
3. `"매매 내역"` 링크를 클릭한다.

**기대결과**
- URL이 `/stocks/trades`로 변경된다.
- 주식 메뉴 항목이 active 스타일로 강조된다.

---

### TC-13. 로고/브랜드 링크 — 대시보드 복귀

**전제조건**
- 로그인된 사용자, 현재 위치 `/budget/transactions`.

**단계**
1. `/budget/transactions`로 이동한다.
2. 사이드바 상단의 `"My Wallet"` 로고 링크를 클릭한다.

**기대결과**
- URL이 `/dashboard`로 변경된다.

## 테스트 데이터

| 데이터셋 | 목적 | 비고 |
|----------|------|------|
| `seed-full` | TC-02 ~ TC-08, TC-11 ~ TC-13 | 수입 3,000,000원, 지출 1,200,000원, 예산 5카테고리, 보유종목 7개, 활동 15건 포함 |
| `seed-over-budget` | TC-06 | 식비 카테고리 달성률 130% 초과 데이터 포함 |
| `seed-loss-portfolio` | TC-04 | 포트폴리오 미실현 손익 음수 (-500,000원) 데이터 포함 |
| `seed-empty` | TC-09 | 모든 컬렉션이 비어 있는 신규 계정 |

> 데이터 시드는 `e2e/tests/seed.spec.ts`의 API 호출 패턴을 따르거나 Playwright `route()` 인터셉트로 목업 대체 가능.

## 병렬 실행 그룹

Playwright `fullyParallel: true` 설정 기준으로, 데이터 의존성에 따라 워커를 분리한다.

| 그룹 | 테스트 케이스 | 공유 데이터셋 | 격리 필요 |
|------|--------------|--------------|-----------|
| A — 정상 렌더링 | TC-01, TC-02, TC-03, TC-05, TC-07, TC-08 | `seed-full` | 아니오 |
| B — 손실/초과 케이스 | TC-04, TC-06 | `seed-loss-portfolio`, `seed-over-budget` | 예 (전용 계정) |
| C — 빈 상태 | TC-09 | `seed-empty` | 예 (전용 계정) |
| D — 로딩/UX | TC-10 | 없음 (route intercept) | 아니오 |
| E — 네비게이션 | TC-11, TC-12, TC-13 | `seed-full` | 아니오 |

> 그룹 A와 E는 동일 `seed-full` 계정을 읽기 전용으로 공유할 수 있다.
> 그룹 B와 C는 데이터 상태가 달라 별도 계정 또는 beforeEach API 리셋이 필요하다.
