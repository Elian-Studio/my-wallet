# Budget E2E 테스트 계획

## 개요
- 대상 페이지:
  - `/budget` — 월별 요약 카드 4종(수입/지출/저축/잔액), MonthPicker, 빠른 링크 2종
  - `/budget/transactions` — 거래내역 목록, 필터(유형/카테고리/날짜), 페이지네이션, 거래 추가/수정/삭제 다이얼로그
  - `/budget/analysis` — 예산 설정 테이블, 예산 추가/수정/삭제 다이얼로그, Recharts 막대차트, 상세 분석 테이블, 카테고리별 달성률 Progress Bar
- 공통 전제조건: 로그인된 상태 (localStorage에 `access_token`, `user` 존재)
- 백엔드 API:
  - `GET /transactions`, `POST /transactions`, `PUT /transactions/:id`, `DELETE /transactions/:id`
  - `GET /categories`
  - `GET /transactions/summary/:year/:month`
  - `GET /budgets`, `POST /budgets`, `PUT /budgets/:id`, `DELETE /budgets/:id`
  - `GET /budgets/analysis`
- 페이지 크기: 거래내역 20건/페이지

## 테스트 시나리오

### 1. /budget — 가계부 개요

#### 1-1. 월별 요약 카드 4종 렌더링
- **전제조건**: 로그인 상태, `/budget` 접근, 현재 월 데이터 존재
- **단계**:
  1. `/budget` 페이지 로드
- **기대 결과**:
  - "수입", "지출", "저축", "잔액" 카드 4개가 표시됨
  - 각 카드에 금액 값이 숫자 형태로 렌더링됨 (로딩 스켈레톤 사라진 후)
  - 잔액 카드는 부호(+/-)가 표시됨(`showSign` 속성)

#### 1-2. MonthPicker로 이전 월 이동 후 요약 갱신
- **전제조건**: 로그인 상태, `/budget` 접근
- **단계**:
  1. MonthPicker의 이전 달 버튼(<) 클릭
- **기대 결과**:
  - MonthPicker에 표시된 월이 1개월 이전으로 변경됨
  - 요약 카드가 로딩 상태를 거쳐 이전 월 데이터로 갱신됨
  - URL 파라미터는 변경되지 않음 (클라이언트 상태)

#### 1-3. 거래 내역 링크 이동
- **전제조건**: 로그인 상태, `/budget` 접근
- **단계**:
  1. "내역 보기" 버튼 클릭
- **기대 결과**:
  - `/budget/transactions`로 이동함

#### 1-4. 예산 분석 링크 이동
- **전제조건**: 로그인 상태, `/budget` 접근
- **단계**:
  1. "분석 보기" 버튼 클릭
- **기대 결과**:
  - `/budget/analysis`로 이동함

### 2. /budget/transactions — 거래 내역

#### 2-1. 거래 목록 테이블 렌더링
- **전제조건**: 로그인 상태, `/budget/transactions` 접근, 거래 데이터 1건 이상 존재
- **단계**:
  1. 페이지 로드 후 로딩 완료 대기
- **기대 결과**:
  - 테이블 헤더(날짜/카테고리/제목/유형/금액) 표시됨
  - 거래 행이 1개 이상 렌더링됨
  - 각 행에 수정(Pencil 아이콘) 버튼과 삭제(Trash2 아이콘) 버튼이 표시됨
  - 총 건수 `(총 N건)` 텍스트가 표시됨

#### 2-2. 유형 필터 적용
- **전제조건**: 로그인 상태, 거래 내역 페이지, 수입/지출/저축 데이터 각각 존재
- **단계**:
  1. 유형 Select에서 "지출" 선택
- **기대 결과**:
  - 테이블에 "지출" 유형 배지를 가진 행만 표시됨
  - 다른 유형(수입/저축) 행은 사라짐
  - 카테고리 Select가 지출 카테고리 목록으로 초기화됨
  - 페이지가 1로 리셋됨

#### 2-3. 날짜 범위 필터 적용
- **전제조건**: 로그인 상태, 거래 내역 페이지
- **단계**:
  1. 시작일 Input에 `2026-03-01` 입력
  2. 종료일 Input에 `2026-03-31` 입력
- **기대 결과**:
  - 테이블에 2026-03-01 ~ 2026-03-31 범위의 거래만 표시됨
  - 범위 밖의 거래 행은 보이지 않음
  - 페이지가 1로 리셋됨

#### 2-4. 페이지네이션 — 다음 페이지 이동
- **전제조건**: 로그인 상태, 거래 내역이 21건 이상 존재 (2페이지 이상)
- **단계**:
  1. 페이지네이션 영역이 표시될 때까지 대기
  2. "다음 페이지"(ChevronRight) 버튼 클릭
- **기대 결과**:
  - 페이지 표시가 "2 / N"으로 변경됨
  - 테이블 내용이 다음 페이지 데이터로 갱신됨
  - "이전 페이지" 버튼이 활성화됨

#### 2-5. 거래 추가 — 정상 흐름
- **전제조건**: 로그인 상태, 거래 내역 페이지, 지출 카테고리 존재
- **단계**:
  1. "추가" 버튼 클릭
  2. 다이얼로그 제목이 "거래 추가"인지 확인
  3. 유형 Select에서 "지출" 선택
  4. 카테고리 Select에서 첫 번째 지출 카테고리 선택
  5. 제목 Input에 "E2E 테스트 지출" 입력
  6. 금액 Input에 `50000` 입력
  7. 날짜 Input에 `2026-03-15` 입력
  8. "추가" 버튼 클릭
- **기대 결과**:
  - 다이얼로그가 닫힘
  - 거래 목록에 "E2E 테스트 지출" 행이 나타남
  - 해당 행의 금액이 `-50,000원`으로 표시됨 (지출은 음수 부호)

#### 2-6. 거래 추가 — 카테고리 미선택 시 검증 오류
- **전제조건**: 로그인 상태, 거래 추가 다이얼로그 열린 상태
- **단계**:
  1. "추가" 버튼 클릭 (다이얼로그 열기)
  2. 제목과 금액만 입력하고 카테고리 선택 없이 "추가" 버튼 클릭
- **기대 결과**:
  - 다이얼로그 내에 "카테고리를 선택해주세요." 오류 메시지 표시됨
  - 다이얼로그가 닫히지 않음
  - API POST 호출이 발생하지 않음

#### 2-7. 거래 수정
- **전제조건**: 2-5 시나리오로 추가된 "E2E 테스트 지출" 거래 존재
- **단계**:
  1. 해당 거래 행의 수정(Pencil) 버튼 클릭
  2. 다이얼로그 제목이 "거래 수정"인지 확인
  3. 제목 Input을 "E2E 테스트 지출 수정됨"으로 변경
  4. 금액을 `75000`으로 변경
  5. "수정" 버튼 클릭
- **기대 결과**:
  - 다이얼로그가 닫힘
  - 해당 행 제목이 "E2E 테스트 지출 수정됨"으로 갱신됨
  - 금액이 `-75,000원`으로 갱신됨

#### 2-8. 거래 삭제
- **전제조건**: 2-7 시나리오로 수정된 거래 존재
- **단계**:
  1. 해당 거래 행의 삭제(Trash2) 버튼 클릭
  2. confirm 다이얼로그에서 "확인" 클릭
- **기대 결과**:
  - "E2E 테스트 지출 수정됨" 행이 목록에서 사라짐
  - 총 건수가 1 감소함

### 3. /budget/analysis — 예산 분석

#### 3-1. 예산 설정 테이블 렌더링
- **전제조건**: 로그인 상태, `/budget/analysis` 접근, 현재 월 예산 1건 이상 존재
- **단계**:
  1. 페이지 로드 후 로딩 완료 대기
- **기대 결과**:
  - "예산 설정" 카드가 표시됨
  - 테이블에 카테고리명, 유형 배지, 예산 금액, 수정/삭제 버튼이 포함된 행이 표시됨
  - "예산 추가" 버튼이 표시됨

#### 3-2. 예산이 없을 때 빈 상태 메시지
- **전제조건**: 로그인 상태, 예산이 없는 월로 MonthPicker 이동
- **단계**:
  1. MonthPicker로 예산이 없는 과거 월 선택
- **기대 결과**:
  - "설정된 예산이 없습니다. 예산을 추가해보세요." 메시지가 표시됨

#### 3-3. 예산 추가 — 정상 흐름
- **전제조건**: 로그인 상태, 예산 분석 페이지, 지출 카테고리 존재
- **단계**:
  1. "예산 추가" 버튼 클릭
  2. 다이얼로그 제목이 "예산 추가"인지 확인
  3. 유형 Select에서 "지출" 선택
  4. 카테고리 Select에서 첫 번째 항목 선택
  5. 금액 Input에 `300000` 입력
  6. "추가" 버튼 클릭
- **기대 결과**:
  - 다이얼로그가 닫힘
  - 예산 설정 테이블에 새 예산 행이 나타남
  - 금액이 `300,000원`으로 표시됨

#### 3-4. 예산 수정 — 금액만 변경 가능
- **전제조건**: 3-3 시나리오로 추가된 예산 존재
- **단계**:
  1. 해당 예산 행의 수정(Pencil) 버튼 클릭
  2. 다이얼로그 제목이 "예산 수정"인지 확인
  3. 유형/카테고리 Select가 비활성(읽기 전용) 표시인지 확인
  4. 금액 Input을 `400000`으로 변경
  5. "수정" 버튼 클릭
- **기대 결과**:
  - 다이얼로그가 닫힘
  - 해당 예산 행의 금액이 `400,000원`으로 갱신됨
  - 카테고리/유형은 변경되지 않음

#### 3-5. 예산 삭제
- **전제조건**: 3-4 시나리오로 수정된 예산 존재
- **단계**:
  1. 해당 예산 행의 삭제(Trash2) 버튼 클릭
  2. confirm 다이얼로그에서 "확인" 클릭
- **기대 결과**:
  - 해당 예산 행이 테이블에서 사라짐
  - 예산이 0건이면 빈 상태 메시지가 표시됨

#### 3-6. 상세 분석 테이블 컬럼 렌더링
- **전제조건**: 로그인 상태, 분석 데이터 존재 (예산 + 거래 모두 있는 월)
- **단계**:
  1. 페이지 로드 후 "상세 분석" 카드까지 스크롤
- **기대 결과**:
  - 테이블에 카테고리/예산/실적/차이/달성률/상태 컬럼이 표시됨
  - 달성률이 `xx.x%` 형식으로 표시됨
  - 상태 컬럼에 StatusBadge가 표시됨
  - 차이 컬럼에 부호(+/-) 포함 금액이 표시됨

#### 3-7. Recharts 막대 차트 렌더링
- **전제조건**: 로그인 상태, 분석 데이터 존재
- **단계**:
  1. 페이지 로드 후 "카테고리별 예산 vs 실적" 카드 확인
- **기대 결과**:
  - `<svg>` 요소를 포함한 차트가 렌더링됨
  - 범례에 "예산", "실적" 항목이 표시됨
  - "표시할 데이터가 없습니다." 메시지가 표시되지 않음

#### 3-8. 카테고리별 달성률 Progress Bar 렌더링
- **전제조건**: 로그인 상태, 분석 데이터 존재
- **단계**:
  1. 페이지 로드 후 "카테고리별 달성률" 카드 확인
- **기대 결과**:
  - 분석 항목 수만큼 Progress Bar가 표시됨
  - 각 항목에 카테고리명, 달성률(%), StatusBadge, 실적/예산 금액이 표시됨
  - 달성률이 100% 초과인 항목은 Progress Bar가 destructive 색상으로 표시되고 "예산 초과" 텍스트가 나타남

#### 3-9. 분석 데이터 없을 때 빈 상태
- **전제조건**: 로그인 상태, 예산도 거래도 없는 월로 이동
- **단계**:
  1. MonthPicker로 빈 월 선택 (예: 3개월 전)
- **기대 결과**:
  - "분석할 데이터가 없습니다." 메시지가 상세 분석 카드에 표시됨
  - "표시할 데이터가 없습니다." 메시지가 차트 영역에 표시됨
  - 달성률 Progress Bar 카드가 렌더링되지 않음

## 병렬 실행 그룹

### 병렬 가능 (test.describe.parallel)
읽기 전용이거나 상태를 공유하지 않는 독립 테스트

| 그룹 | 테스트 케이스 | 테스트 수 | 이유 |
|------|-------------|----------|------|
| 개요 페이지 읽기 | 1-1, 1-2, 1-3, 1-4 | 4 | 데이터를 변경하지 않음. 각 테스트가 독립 세션 사용 |
| 거래 목록 읽기 | 2-1, 2-2, 2-3 | 3 | 필터 조작만 수행. DB 변경 없음 |
| 페이지네이션 | 2-4 | 1 | 읽기 전용, fixture 데이터에만 의존 |
| 분석 읽기 | 3-1, 3-2, 3-6, 3-7, 3-8, 3-9 | 6 | 조회 전용. CRUD 없음 |

### 순차 실행 (test.describe.serial)
이전 단계 결과(DB 상태)에 의존하는 CRUD 체인

| 그룹 | 테스트 케이스 | 테스트 수 | 이유 |
|------|-------------|----------|------|
| 거래 CRUD 체인 | 2-5 → 2-6 → 2-7 → 2-8 | 4 | 2-7은 2-5가 추가한 레코드에 의존. 2-8은 2-7 수정 결과에 의존 |
| 예산 CRUD 체인 | 3-3 → 3-4 → 3-5 | 3 | 3-4는 3-3이 생성한 예산 ID에 의존. 3-5는 3-4 수정 상태에 의존 |

> **비고**: CRUD 체인 그룹은 각각 독립적이므로 거래 CRUD와 예산 CRUD는 서로 병렬 실행 가능.
